Suggested time: 75 seconds

7. Order transaction
Suggested time: 80 seconds

SAY IN YOUR OWN WORDS
The API validates the customer and request. It locks the customer before checking the repeat key, then locks candidate stock rows in a consistent order. It chooses one warehouse that can supply all items. Reservation, costs, order, simulated payment, shipment and audit data belong to one transaction. An error rolls back uncommitted changes. If the browser retries a request with the same key and matching details, the API returns the existing order. If the details differ, it rejects the conflict.

Explain idempotency using a lost network response rather than unexplained jargon.

IF ASKED

10. Forecast method
Suggested time: 90 seconds

SAY IN YOUR OWN WORDS
History comes from a separate seeded or imported daily-sales dataset. Eligible series require at least thirty-five observations and recent history. Features include demand one, seven and fourteen days ago, a shifted seven-day mean, weekday and trend. Earlier dates train the model and later dates form the holdout. Predictions proceed recursively without inserting future actual values. A weekly baseline repeats the last training week. The lower mean absolute error chooses the model, which then refits on available history and forecasts tomorrow onward.

SHOW / TRANSITION
Explain that a new operational order changes stock but does not automatically retrain the model.

IF ASKED
The same holdout supports model selection, so it is not an independent final test. Real deployment requires representative data and rolling-origin evaluation. Random Forest is an algorithm. TensorFlow is a framework, not automatically a better model.
